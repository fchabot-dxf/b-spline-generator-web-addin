## What's GOOD (per the STANDARDS-AUDIT convention of naming healthy parts, not just gaps)

- **`bspline-frame-builder.py`'s OWN run()/stop() symmetry is clean.** Enumerated what `run()`
  registers vs what `stop()` releases (the explicit ask in NEXT-SESSION for P2/P3):
  - `run()` registers: 1 refresh CustomEvent (session-scoped, intentionally never released — documented
    at `:689-691`); 3 top-level command defs + handlers (`handlers` list); 1 hidden reload command +
    handler; 3 toolbar panels (`bsplinePanel_<tab>` × SolidTab/SketchTab/MillingTab) + their controls;
    5 sub-add-ins' own `run(context)` calls (each sub owns its own resources — P3 isolation).
  - `stop()` releases, in order: `_teardown_submodules()` (delegates to each sub's own `stop()` in
    REVERSE run order, clears sketch/solid handler lists, removes sketch's `documentActivated` sub, nulls
    all sub-module globals) → removes every panel whose id starts with `bsplinePanel` across ALL tabs →
    deletes the 5 command defs → closes 4 named legacy palettes → `handlers.clear()` in `finally` (always
    runs, even on exception).
  - Every sub-module load (`_bootstrap()`) and every sub-module `run()`/`stop()` call is individually
    `try/except`-wrapped (`bspline-frame-builder.py:265-304`, `:667-676`, `:368-376`) — P3 isolation is
    genuinely honored at the orchestrator layer; one bad sub-module cannot take down the others or block
    the rest of teardown.
  - **Verdict: no P2/P3 violation in this file itself.** The one open lifecycle bug (A1-2/B5) is inside a
    sub-module that owns its own cleanup — correctly out of the parent's responsibility per the P3 design.
- `fb_shared/build_info.py` — clean, accurate docstrings, pure-stdlib, never raises, does what it says. No findings.
- `release.py` — matches STANDARDS-AUDIT §5's description exactly (git-push → Cloudflare auto-rebuild;
  never touches the workers directly); step ordering, flag parsing, and the Claude-CLI-with-fallback
  commit-message chain are all straightforward and match their own docstrings.
